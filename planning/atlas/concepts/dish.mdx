## The problem

The editor needs the full result of parsing a book: every piece of markup, how the pieces nest, the problems found, suggested fixes, and where each chapter and verse sits. It asks again as the translator types, and a book is one file, so each ask covers a whole book. Building thousands of JavaScript objects and strings for that on every ask would be slow.

## The solution

One parse becomes one buffer: a short header, a table of contents for the buffer, and ten sections of fixed-size number rows. Positions are numbers pointing into the text the editor already has, so almost no strings cross. The obvious alternative is converting the parse to JSON or JavaScript objects; that copies every string and allocates per item. The buffer also ships the parse tree itself, so any consumer can build its own views (blocks, lines, footnote contents) without the engine guessing which ones it wants.

## Trade-offs

- Readers must match the format version (now 5). A layout change means a new version and regenerated readers.
- Every section is always listed, even when empty, so a few bytes go to sections a caller did not ask for.
- Values are raw numbers; reading them needs the generated reader, not a debugger glance.

## Show me

The first 32 bytes of the scratch book's dish (`plate` with `toc` and `diagnostics`). Look at how much is said by plain numbers:

```text
4f 4e 57 52   "ONWR"        magic
05 00 00 00   5             format version
0a 00 00 00   10            section count
00 00 00 00   0             flags (bit 0 = offsets are UTF-16)
ff ff ff ff   NONE          declared \usfm version
7d 00 00 00   125           source length
10 2a 39 c5 03 f0 40 7b     xxh3-64 of the source bytes
```

The ten sections, in wire order:

```text
tokens  nodes  childIds  diagnostics  fixes  edits  fixText  chapters  verses  members
```

## How it works

- **The tree is the product.** `tokens`, `nodes` and `childIds` are the [[cst]] as it lives in Rust.
- **Optional sections are empty, not absent.** The directory always lists all ten, so a reader indexes by slot.
- **`end`, not `len`, on a token.** Every offset field is a plain source offset, so one sorted sweep converts the whole dish to [[utf16]].
- **The source hash** answers "is this the parse of that text" without holding both (`xxh3Text(text) === dish.sourceHash`).
- **The declared `\usfm` version always crosses,** because it gates severities before a single finding can be shown.

## Composes with

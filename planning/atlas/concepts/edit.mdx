## The problem

Lint fixes, format, diff merges and overlay all propose changes to a file the editor owns. A change shape per feature means an applier per feature.

## The solution

Every writer returns splice edits, a byte range plus replacement text, and never a new document ([[invariants]] 1, 3). Untouched bytes stay untouched, each change can be previewed alone, and one reference applier serves tests and other bindings. Why returning a whole new document was rejected is not recorded.

## Trade-offs

- Offsets are bytes; the editor converts to UTF-16 at the boundary ([[utf16]]).
- A set of edits is valid only against the exact text it was computed from.
- Two inserts at one point merge, so last-to-first application keeps their order.

## Show me

The shape, and what overlay returns for one passage (from `galley/src/overlay.md`):

```text
Edit { from, to, insert }        replace source[from..to] with insert

overlay(target, source) → 6 edits, ascending, non-overlapping
  insert "\p\n"   at the target's \v 21
  insert "\n\q1" "\n\q2" "\n\q1" "\n\q2"   after verse 23's text   ← one edit, shared position
```

## How it works

`edit.rs`: three speakers in onion (lint fixes, the formatter, the diff port) and one in galley ([[overlay]]). An editor applies all of them as byte splices through its UTF-16 shim. [[code:onion/src/edit.rs#check_edits]] validates a set before it is applied; `apply` and [[code:onion/src/edit.rs#apply_splices]] are the reference appliers.

## Composes with

Produced by [[lint]], [[format]], [[diff]] (`to_edits`, `SpliceEdit`) and [[overlay]]. Indexes the [[source]].

Each rule: the invariant, why we hold it and what the alternative would cost, and what it forces in the code.

## 1. Lossless: bytes in are bytes out

**Why.** Most parsers build an AST, and an AST applies the spec's whitespace reduction and normalises closers. Load-then-save through it rewrites spacing the translator never touched, so every save is a diff and collaborators conflict in git over bytes neither changed. We could normalise; it would make loading lossy.

**Forces.** Tokens tile the source: concatenating their spans is the file ([[scanner]], [[source]]). Horizontal whitespace past a marker's one delimiter byte is its own token kind, `Pad`, not dropped (875 sites flagged across the corpus when it landed, 8128053) ([[token]]). Closers the file never wrote are never inserted: each node records how its frame ended, `Explicit`, `Implicit`, `Recovery` or `Eof`, in one byte ([[cst]], [[walker]]). Loss happens only in projections named as lossy: [[mask]], [[exports]], [[vref]].

## 2. Offsets over object graphs

**Why.** Sefer reparses on every keystroke, and the answer crosses into JS. A string per token is a heap allocation in Rust and another in JS; JSON adds an encode and a parse on top. Integers are small, live in flat arrays and copy for free. Measured in Node, encoding was the cost and the copy was free (13c3d3b).

**Forces.** A [[token]] is 12 bytes of numbers (`start u32 · len u16 · kind u8 · marker u8 · level u8`, size asserted) and holds no text. Interiors are read lazily ([[designator]], [[attributes]]). Every per-call answer is a binary wire: from/to ranges, enum-numbered kinds, string tables only where text must travel ([[wire]], [[plate]], [[dish]]). Shipping tokens, CST and diagnostics instead of thirteen prebuilt views was 0.64x the bytes and 0.62x the time (b781bb9). JSON is kept for two cold paths, [[diff]] and [[resolve]].

## 3. Flag, never repair

**Why.** A repair is a guess. A silent one moves the editor's offsets and hides the mistake from the person who has to fix it.

**Forces.** Input that cannot be represented is refused with a reason, never defaulted (GLOSSARY, "Refuse, never invent"). [[lint]] moves, inserts and drops no token; a fix is an offered list of [[edit]]s and exists only where the row declares one. A malformed designator keeps its [[toc]] row with numbers 0; a broken attribute pair is `Malformed` ([[attributes]]); [[resolve]] says ambiguous rather than picking the nearest. [[format]] is the one opt-in path that writes new bytes.

## 4. Engines are stateless; galley holds all state

**Why.** Caches spread across features disagree about what is current, and wasm memory grows and never shrinks. One owner can key everything by content and account for every byte.

**Forces.** [[onion]] and [[sous-core]] are text in, answers out; `parse` returns bytes and retains nothing. [[galley]] has one caching layer, the [[pantry]]: books arrive whole through `update(id, text)` with no splice API, so offsets inside a book cannot drift; products are content-addressed; a budget attributes every resident byte.

## 5. The chapter is the unit of rework

**Why.** An edit lands in one chapter. Reparsing or recounting the whole book, or the whole Bible, per keystroke is the cost to avoid, and content keys mean nothing needs invalidating: a changed chapter simply misses.

**Forces.** Onion cuts at `\c` and carries the few cross-chapter facts in an explicit `Carried` ([[chunk]]); the [[chunk-cache]] keys a chapter's products by its bytes, and the assembled dish is byte-identical to a cold parse. Every Sous rule is map, fold, judge, with map a pure function of one chapter ([[chapter-pass]]).

## 6. Author once, generate the rest, test for staleness

**Why.** Two hand-kept copies of a fact drift silently: a moved wire field reads garbage, a spec change misses one `if`. Before generation, onion-wasm.ts mirrored 109 constants by hand (b781bb9).

**Forces.** The [[marker-table]] generates the Rust lookup, the name matcher and the TS table. [[ticket]] generates each wire's Rust writer and TS reader from one declaration. `diagnostics.json` is generated from lint's catalog, and mise's Unicode tables from a pinned UCD. Generated files are checked in, and a test fails when one is stale. The [[corpus]] envelope and the Sous snapshot reader are the standing exceptions.

## 7. Sous judges from the project's own counts, behind a neutral seam

**Why.** Most target languages have no dictionary, model or style guide, and conventions differ: French spaces inside guillemets, Amharic writes `::` for its full stop. A fixed rule list is wrong per language; the project's own counts are not. And a proofreader tied to the USFM parser could not read vref or any other producer.

**Forces.** [[sous-core]] never depends on onion; it reads a `ProjectedBook` that galley builds ([[onion-book]]). Facts both need live in the zero-dependency [[mise]]. A verdict is a fraction with numerator, denominator and support floor, never a blended score ([[sous-chef]]).

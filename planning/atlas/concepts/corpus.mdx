## The problem

A cold open parses every book. Sixty-six dishes are 66 crossings and 66 handles, and the caller keys books by its own ids (paths, database ids) that the engine has no business interpreting.

## The solution

`ONCP` frames the per-book dishes byte for byte under opaque caller labels, so one reader decodes a book or a project the same way ([[invariants]] 2). The engine never reads the labels. Books can be parsed in parallel before framing.

## Trade-offs

- A cold load does not warm the [[chunk-cache]], so the first edit reparses (marked TODO).
- No per-entry checksum; adding one is a format change (16 to 32 bytes an entry).
- Read by hand, not generated: standing debt against [[invariants]] 6.

## Show me

Two books framed together; look at the header, then one directory entry per book. From `galley/src/corpus.rs`:

```text
galley::corpus::plate(&[("GEN", gen_dish), ("EXO", exo_dish)])

bytes[0..4]    "ONCP"            magic
bytes[4..8]    1                 format version
bytes[8..12]   2                 book count
bytes[12..16]  0                 reserved
bytes[16..]    [keyAt, keyLen, dishAt, dishLen] x 2, then the bodies
```

## How it works

- **Frames, never re-encodes.** Each body is exactly what [[plate]] writes for one book.
- **Parallelism is the caller's.** Parsing is embarrassingly parallel per book: 28.80 ms on 10 threads against 158.38 ms serial for the English Bible.
- Not yet wired to the [[pantry]]: no chunk-cache seeding, no per-book checksum.

## Composes with

Frames [[dish]] buffers. Not yet wired to the [[pantry]].

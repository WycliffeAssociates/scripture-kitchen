## The problem

Lint, mask, the exports and the dish all need containment: is this word inside a note, which paragraph holds verse 4. And load-then-save through the engine must reproduce the file exactly, or every save rewrites spacing and two collaborators conflict in git over bytes neither touched.

## The solution

A concrete tree over the token stream, not an AST ([[invariants]] 1). An AST applies the spec's [whitespace reduction](https://docs.usfm.bible/usfm/3.1/whitespace.html#ws-reducing) and normalises closers, so loading through it is lossy. USJ and USX are lossy for the same reason: their key:value shape cannot hold every USFM byte, and it forces an object graph. So the library keeps USFM itself as the document and answers in string offsets into it. Two things keep this one lossless. Whitespace past a marker's one delimiter byte is a `Pad` token: kept, flagged by lint, dropped only by text views. And a frame the file never closed is closed **implicitly**: the node records `Implicit`, `Recovery` or `Eof` in its `reason` byte, and no `\ft*` or `\f*` token is invented.

Chapters and verses are Points (siblings), not containers, because verse and paragraph boundaries cross; the [[toc]] addresses them.

## Trade-offs

- Traversing the tree as an editor is opaque without knowing USFM: which markers nest, which are Points, why a `\p` closed. There are no ready-made views; blocks, lines and note interiors are each consumer's to build.
- Whitespace the spec would collapse is kept, so a file can carry extra spaces where none are needed; lint flags them as Pad rather than removing them.
- Broken input still gets a tree. An unclosed `\f` closes by `Recovery`, and lint reports it.
- Building it costs about 40% on top of a lex; the heaviest real book builds in about 0.6 ms.

## How it works

- **Lossless, not abstract.** Every token id sits in exactly one child list, so an in-order walk of the tree gives back the [[scanner]]'s stream and the bytes concatenate to the [[source]]. `cst_oracle.rs` proves the partition over the test corpus. An AST would have to choose what to drop; the [[exports]] make that choice later and say they are lossy.
- **Points are siblings.** `\c` and `\v` take no content, so paragraphs are their siblings. Chapters and verses are an index over the tree, the [[toc]], not a nesting of it.
- **The walker records verdicts, lint reads them.** Each node stores a [[code:onion/src/cst.rs#CloseReason]] (Explicit, Implicit, Recovery, Eof) and the stamped context. [[lint]] matches on those and never re-derives how a frame ended. Positional context (BookHeaders and the rest) is lint's, not the tree's.
- **Flat arrays, no pointers.** `nodes` plus one shared `child_ids` arena; a node id is tagged with bit 31 so tokens and nodes mix in document order. It crosses the wall as three sections of the [[dish]] without conversion, and shipping the tree rather than prebuilt views is what keeps the [[plate]] small.
- **Streaming build.** [[code:onion/src/cst.rs#Builder::feed]] takes one token at a time and holds no slice. That is what lets [[code:onion/src/cst.rs#build_chunk]] build one chapter and simulate the next `\c`'s displacement, which is how the [[chunk-cache]] reuses trees.

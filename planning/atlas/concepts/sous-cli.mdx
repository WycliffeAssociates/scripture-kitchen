## Why

- **An adapter, not an engine.** The CLI owns file discovery and Onion adaptation; core owns validation, alignment and the scans; galley owns UTF-16 publication (`main.rs` doc). The charter calls it the first host adapter and says to extract a shared adapter crate only when a second consumer needs it.
- **Output is a debug view** while the finding contract freezes.

Doc gap: `architecture.md` says sous-cli "depends on both only to call them"; its `Cargo.toml` depends on three: [[sous-core]], [[galley]] and [[onion]] (default features off).

## Composes with

Calls [[sous-core]], [[galley]] (publication, `Expediter`) and [[onion]]. Part of [[sous-chef]].

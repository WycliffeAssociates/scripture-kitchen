## The problem

The proofreader has to count a translation's habits, like which character usually follows a comma or how long verses run, and judge outliers. That counting should work on any source of verse text, not only USFM files. If it depended on the USFM engine, it would be tied to one file format forever.

## The solution

sous-core takes a plain, format-neutral view of a book: its text, plus where each chapter and verse starts. It never imports the USFM engine; [[galley]] builds that view from USFM and hands it over. It also keeps no caches between calls; galley decides what to reuse, and sous-core says what is safe to reuse. Its only shared dependency is [[mise]], the tiny leaf crate both engines use.

## Trade-offs

- It cannot ask the USFM engine anything directly. Any structural fact it needs must be in the neutral view.
- It owns content evidence only. Editor positions, saving, file reading and translated messages belong elsewhere.
- It generates its own TypeScript reader instead of using [[ticket]]; `architecture.md` lists that as debt.

## How it works

- **Never depends on onion.** "Do not add the dependency" (`architecture.md`). A vref corpus can produce the same view.
- **Owns content evidence only.** Unicode classification, config-free observations, corpus reductions, judging, finding serialization (`charter.md`, "Sous owns content evidence").
- **No resident caches.** sous-core declares what is safe to reuse (`SCHEMA`, `RETAIN_CHAPTERS`).
- **Its own reader emitter.** Its numbers are generated and its reader typed.

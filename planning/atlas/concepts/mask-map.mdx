## The problem

A host often works on the readable text of a book: the verses with markup and footnotes removed, say for a proofreading view. When it finds something at position 120 in that text, it needs the matching position in the actual file. Asking the engine for every such lookup means a round trip across the WebAssembly boundary each time.

## The solution

The engine sends the [[mask]]'s list of kept file ranges once, as plain pairs of numbers. The host's reader joins them to rebuild the readable text and maps positions back to the file on its own, with no further calls. The obvious alternative is a lookup call per position. The map also carries the file length, so a host cannot apply it to the wrong version of the file.

## Trade-offs

- It can be bigger than the text it describes. On a word-aligned translation each word and each space is its own range: 12.9 MB of map for 4.2 MB of text. For those, keep the string instead.
- No compressed form. Run-length pairs would halve the aligned case but do not fit the fixed-size row vocabulary.
- The prefix sums that make lookups fast are rebuilt by the reader at open, not sent.

## Show me

Rebuilding the verse text from the ranges, then mapping a search hit back. Then the byte layout. From `galley/src/mask.md`:

```js
const map = MaskMap.open(galley.mask("books/MRK.usfm", { utf16: true }));
let reading = "";
for (let n = 0; n < map.rangeCount; n++) {
  const r = map.range(n);
  reading += source.slice(r.sourceFrom, r.sourceTo);   // === galley.verseText(id)
}
map.toSource(hit.projectedFrom);
```

```text
0  magic "MASK"   4 version 1   8 flags (bit 0 UTF-16)   12 recipe (0 verseText, 1 structure, 2 text)
16 rangeCount     20 sourceLen  24 projectedLen          28 rangeCount × (sourceFrom u32, sourceTo u32)
```

## How it works

- **`starts` is not on the wire.** It is the prefix sum of range lengths; the reader builds it in one pass at open. Four bytes a range saved for a value derived in microseconds.
- **`sourceLen` refuses the wrong revision** before a consumer joins slices out of the wrong string; `projectedLen` checks the join.
- **Cost.** en_ulb verseText: ~80 k ranges, ~645 KB of wire for ~4.1 MB of text. en_ult (word-aligned): 12.9 MB map against a 4.2 MB projection.
- **No run-length form** (`gap u16, keep u16`): not [[ticket]]'s fixed-width vocabulary.

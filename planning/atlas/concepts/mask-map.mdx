## The problem

A host working on projected text (a proofreading view, say) needs source offsets for many positions. A wasm call per lookup is a crossing each time.

## The solution

Send the [[mask]]'s ranges once, as integer pairs plus the source length ([[invariants]] 2). The generated reader rebuilds the text and maps offsets locally. The length stops it being applied to another version of the file.

## Trade-offs

- It can outweigh its text: on aligned data every word and space is a range, 12.9 MB of map for 4.2 MB of text. Keep the string there instead.
- No compressed form; run-length pairs would halve the aligned case but do not fit fixed-stride rows.
- The reader rebuilds the prefix sums at open; they are not sent.

## Show me

Rebuilding the verse text from the ranges, then mapping a search hit back. Then the byte layout. From `galley/src/mask.md`:

```js
const map = MaskMap.open(galley.mask("books/MRK.usfm", { utf16: true }));
let reading = "";
for (let n = 0; n < map.rangeCount; n++) {
  const r = map.range(n);
  reading += source.slice(r.sourceFrom, r.sourceTo);   // === galley.verseText(id)
}
map.toSource(hit.projectedFrom);
```

| offset | field |
| --- | --- |
| 0 | magic `"MASK"` |
| 4 | version 1 |
| 8 | flags (bit 0 UTF-16) |
| 12 | recipe (0 verseText, 1 structure, 2 text) |
| 16 | rangeCount |
| 20 | sourceLen |
| 24 | projectedLen |
| 28 | rangeCount × (sourceFrom u32, sourceTo u32) |

## How it works

- **`starts` is not on the wire.** It is the prefix sum of range lengths; the reader builds it in one pass at open. Four bytes a range saved for a value derived in microseconds.
- **`sourceLen` refuses the wrong revision** before a consumer joins slices out of the wrong string; `projectedLen` checks the join.
- **Cost.** en_ulb verseText: ~80 k ranges, ~645 KB of wire for ~4.1 MB of text. en_ult (word-aligned): 12.9 MB map against a 4.2 MB projection.
- **No run-length form** (`gap u16, keep u16`): not [[ticket]]'s fixed-width vocabulary.

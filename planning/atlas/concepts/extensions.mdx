## The problem

Projects declare `\z` markers in `markers.ext` (`\zaln-s`…`\zaln-e` around every aligned word), and a translation and its references can come from different projects with different lists.

## The solution

USFM's own [User Extensions](https://docs.usfm.bible/usfm/3.1/extensions.html) rule: a project names `z` markers in `markers.ext` and gives each a spec `\category`. Each category maps to a template row that already has its behaviour, and from then on the scanner, walker, lint, mask and exports treat the marker as that row. There are no per-marker rules: the category already says how it nests and closes. Lists are per book ([[code:onion/src/scanner.rs#lex_with]]), so two projects coexist in one process.

## Trade-offs

- Changing the installed list invalidates every product built under it.
- A `\z` marker the list does not name is inert: no nesting, no lint, no export shape.
- Unprefixed legacy names like `\s5` are allowed only where no real marker has that spelling.

## Show me

A spec-conformant `markers.ext` entry, then a verse that uses it:

```usfm
\marker zmyc
\category char
\description A character marker extension.
\attribute x-myattr1
```

```usfm
\p \v 1 In the beginning \zmyc God|x-myattr1="H0430"\zmyc* created.
```

Registered as `char`, `\zmyc` nests, closes and takes attributes like `\w`. Registering `zaln` as a milestone makes it pair like `\qt-s`; relaxing the prefix lets `\s5` be a bare point:

```rust
let zaln = CustomMarker { name: "zaln".into(), category: Milestone, description: String::new(), attributes: vec![] };
set_extensions(&[zaln]);
lex("\\zaln-s |x-strong=\"H0430\"\\*word\\zaln-e\\*");
// Milestone { end: false }, marker_idx = zms: pairs and takes attributes like \qt-s

let s5 = CustomMarker { name: "s5".into(), category: Standalone, description: String::new(), attributes: vec![] };
set_extensions_with(&[s5], &ExtensionOptions { relax_z_prefix: true });
lex("\\p \\v 1 a \\s5 \\v 3 b");
// \s5 is a bare point; the \p stays open past it
```

At the JS wall (`onion-wasm/README.md`), bad entries come back with a reason:

```ts
customMarkers([{ name: "zmyf", category: "footnote" }, { name: "nope", category: "char" }])
// → { markers: [{ name: "zmyf", category: "footnote" }], relaxZPrefix: false,
//     malformed: [{ name: "nope", reason: "name does not start with z" }] }
```

## How it works

- **A name maps to a template row and stops.** Every behaviour (caller, note scope, closing, lint contexts, mask, export shape) is the [[marker-table]] row's. The one thing a template cannot carry is the spelled name, which is what [[code:onion/src/tables/generated.rs#is_extension|generated::is_extension]] is for.
- **Legacy names add, never redefine.** `relax_z_prefix` admits en_ulb's `\s5` because no spec spelling resolves it.
- **Per book, not per process**. Each [[pantry]] book lexes by the list it was registered with.
- **Lists key the caches.** The [[chunk-cache]] key holds the list's fingerprint, so equal lists share parses and different lists never do.

## Composes with

Read by the [[scanner]] (`lex_with`) to resolve `z` lexemes against the [[marker-table]]. `mise::extensions::parse_markers_ext` ([[mise]]) translates a file into the list. Galley's [[pantry]] stores a `Markers` per book.

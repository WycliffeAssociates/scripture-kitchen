## The problem

Per-keystroke calls over a whole project need memory between calls, and Sous needs onion's view of the text. But both engines stay stateless, and Sous must not depend on onion.

## The solution

Galley is the only adapter allowed to see both ([[invariants]] 4, 7). All state lives in one cache, the [[pantry]]; the [[onion-book]] seam builds Sous's neutral input; the [[expediter]] publishes. Neither engine depends on galley.

## Trade-offs

- It is stateful: answers are only as current as the host's last `update`, and each update sends a whole book, not a splice.
- Retained products cost memory, about 1.6x a target's text ([[pantry]]), and wasm memory grows and never shrinks.
- Building it for JS pulls the whole engine in through [[onion-wasm]].

## Show me

The modules, one job each:

| module | job |
| --- | --- |
| `galley::pantry` | the one caching layer (chunks, books, derived stores, budget) |

| `galley::overlay` | match formatting |

| `galley::corpus` | the ONCP envelope |
| `galley::wasm` | the Galley handle (feature `wasm`) |

## How it works

- **The only place the engines meet.** "Anything that might be considered stateful lives here and NEVER in the engines" (`galley/src/lib.rs`). `galley::sous` owns the Onion→Sous seam entire.
- **One caching layer.** Everything kept between calls is in the [[pantry]] or a store it defines (`architecture.md`).
- **The JS superset.** galley's cdylib links onion-wasm's shims, so one module exports [[code:galley/src/wasm.rs#Galley]] and every onion door. A test pins the exact export list because a cdylib silently drops what nothing references.
- **Depends on** [[onion]], [[sous-core]], [[mise]], [[ticket]]; [[onion-wasm]], `wasm-bindgen` and serde only under `wasm`; `rayon` only under `parallel`.

## Composes with

Implements the [[pantry]], [[chunk-cache]], [[expediter]], [[onion-book]], [[find]], [[overlay]] and the [[census]], [[mask-map]], [[find-buffer]] and [[corpus]] wires. Ships as the [[galley-package]].

## The problem

A translator has two copies of the same book: the one on their machine and the one a colleague edited. They need to see what changed, verse by verse, and pick which wording to keep. A line-based diff is the wrong unit: one reflowed paragraph shows as dozens of changed lines, and it cannot say "verse 3 changed".

## The solution

We cut each copy into blocks at chapter and verse markers, line the blocks up, and report each verse as unchanged, modified, added or deleted. The cut points already exist in the [[toc]], so we reuse them instead of re-reading the file. A merge is then just "for each verse, take this side", written back out as text or as a list of [[edit]]s the editor can replay. Inside a modified verse, the caller can ask for word-level or character-level detail. A verse that moved is shown as a deletion plus an addition: we do not detect moves.

## Trade-offs

- No move detection. A verse out of order appears twice, once deleted and once added (0.1.8).
- The result crosses to JavaScript as JSON, not packed numbers. It is the one rich export, accepted because it runs rarely, when the editor opens a comparison view, not per keystroke.
- With word-level detail on, JSON for 66 books grows from 221 KB to 6.2 MB. A binary format is parked until someone needs it.
- Word boundaries never cross a footnote edge, so a footnote is compared as its own text.

## How it works

- **Three layers, one walk.** Identity: a block is the bytes between two [[toc]] anchors, a `Range<u32>` plus a `Copy` address. Alignment: Myers over 12-byte addresses, then coalescing pairs a rebridged or relabeled verse into one decision. Projection: `merge` emits bytes, `to_edits` emits replay splices. PSA against itself: 2.2 ms (commit 09b76e2).
- **Changed units only** unless `unchanged: true` (0.1.8).
- **Runs are asked for by name.** `"none"`, `"words"` (UAX-29) or `"chars"`; an unknown name rejects. The [[cst]] and the `text` [[mask]] are built only when runs are asked for.
- **JSON at the wall.** serde keeps the old editors' camelCase contract (planning item 2026-09-28, binary run wire not scheduled).

## Composes with

Reads the [[toc]] per side, and the [[cst]] and the `text` [[mask]] cut only when runs are asked for. Emits [[edit]]s (`to_edits`, `SpliceEdit`) for replay. Contrast with [[plate]]: diff is the exception to "nothing rich crosses".

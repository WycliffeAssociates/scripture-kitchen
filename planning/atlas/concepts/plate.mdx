## The problem

The editor calls the engine on every keystroke, and each call is about a whole book, because USFM keeps one book per file. It wants several answers at once: the tokens, the tree, the lint problems, where each chapter and verse starts. Asking for each separately pays the cost of crossing from WebAssembly to JavaScript several times. And converting results into JavaScript strings and objects is where the time goes; copying raw bytes is nearly free.

## The solution

Parse once, then "plate" the result: write all of it into one flat buffer of numbers and hand that buffer over in one call. JavaScript reads rows straight out of the buffer with a generated reader, and only the rows it asks for. Text is not copied; rows hold byte positions into the file the editor already has. The engine keeps nothing between calls, so there is nothing to free.

The old design built thirteen prepared views of the book and converted each one for JavaScript. Three fifths of that call was building and converting views. Sending the raw tree instead took 0.64x the bytes and 0.62x the time.

Rust callers can stop before plating and use the parsed result directly.

## Trade-offs

- The buffer is a versioned format (now version 5). Changing its shape means every consumer updates its reader.
- JavaScript gets a cursor over numbers, not friendly objects. Any convenience view is the consumer's to build.
- Two cold paths still return JSON: [[diff]]'s skeleton and [[resolve]]'s answer.

## Show me

Native callers stop at `parse`; anything crossing to JavaScript calls `plate`.

```text
onion::wire::parse(text, opts)   -> Parsed    native callers stop here
onion::wire::plate(&parsed)      -> Vec<u8>   the dish, for anything crossing
```

```ts
const { tree, tokens, diagnostics, toc } = deserialize(parse(text, { diagnostics: true }));
```

The scratch book in [[cst]] plates to 1,072 bytes with `toc` and `diagnostics` on.

## How it works

- **Ship the tree, not projections.** Tokens + CST + diagnostics was 0.64x the bytes and 0.62x the time of the thirteen curated planes `analyze` used to build; three fifths of `analyze` was building and converting planes (commit b781bb9).
- **One call, several products.** Crossing a typical book cost ~80 µs, which is what forces several products into one call. Statelessness stayed: `parse` returns bytes and retains nothing, so there is nothing to free.
- **Nothing rich crosses.** Flat `Uint32Array` copies plus a few strings. JS never holds a token object; the generated reader is lazy and decodes a row only when asked.
- **Copy is free, encode is the cost** (commit 13c3d3b, measured in Node: analyze 1.4–1.5x native).
- **Exceptions.** JSON on cold paths: [[diff]]'s skeleton (old camelCase contract) and [[resolve]]'s answer.

## Composes with

Reads `Parsed`: the [[token]]s, the [[cst]], an optional [[lint]] report and [[toc]]. Writes the [[dish]]. The galley [[chunk-cache]] builds a `Parsed` with `Parsed::from_parts` from cached chunks and plates it byte-identically.

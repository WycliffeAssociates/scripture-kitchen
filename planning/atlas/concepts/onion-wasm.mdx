## Show me

```ts
import { parse } from "onion-wasm";
import { deserialize } from "onion-wasm/schema";
const { tree, tokens, diagnostics, toc } = deserialize(parse(text, { diagnostics: true }));
```

```js
galley.parseText(text, { tco: true });   // throws: parseText: unknown option "tco"; expected diagnostics, toc or utf16
```

## Why

- **Nothing is implemented here.** Every export tags a library function, plus an offset conversion or a small wire struct where the wall demands it. "You could delete this crate and recreate it in an afternoon; that is the point" (`README.md`).
- **Byte-identical binaries.** `build.sh` remaps `$CARGO_HOME` and the sysroot and strips the `producers` section, so the same source builds to one sha on macOS/arm64 and Linux arm64/x86_64. That lets CI gate the binary, not just its interface. Release builds now run on x86_64 Linux via `wasm-build.sh`.
- **Committed packages.** Not on npm; consumers install from a git tag, so `pkg-web`/`pkg-bundler` are checked in. ~370 KB, ~152 KB gzipped, one build per target.
- **Options are checked.** Every option bag is a declared interface; an unknown key throws by name rather than reading as `false` (0.1.7).
- **UTF-16 at the wall, LF in.** Offsets out are CodeMirror code units; CRLF input would put them one ahead per line.

## Composes with

Depends on [[onion]] and [[mise]]. Linked into [[galley]] under the `wasm` feature, which is how the [[galley-package]] exports every onion door. Ships the [[dish]] reader generated by the [[plate]] codegen.

## The problem

A browser USFM editor shows the outline, goes to a verse, underlines errors, searches and surfaces Sous findings while the translator types, and should carry no scripture parser of its own.

## The solution

Sefer parses nothing itself. Every answer about USFM comes from the [[galley-package]], with offsets in UTF-16 ([[utf16]]) so it converts nothing. It is one host of the package, not the reason for its shape. The same npm package carries the shared domain libraries: [[canon]] for books and numbering, [[bento]] for manifests, and [[bttwriter]], loaded only on the migration screen, for BTT Writer projects.

## Trade-offs

- A feature it needs must land on the galley package, the only build it vendors, not just on the engine.
- Its internals live in another repo; the atlas does not document them.

## Show me

Asking where a verse is:

```ts
const verse = { kind: "verses", from: { chapter: 1, verse: 2 }, to: { chapter: 1, verse: 2 } };
galley.resolve("books/LUK.usfm", verse, { utf16: true });
// { found: { from, to, opening, covers, coarser } }
```

## Composes with

Reads the [[galley-package]]'s wires: [[dish]], [[census]], [[find-buffer]], [[mask-map]], [[findings-snapshot]]; and [[resolve]]'s answers. Calls [[bento]] and [[bttwriter]] once it switches to them; `planning/items/2026-11-05-sefer-adopts-bento-and-bttwriter-what-moves-what-s.mdx` lists what moves.

## The problem

Find runs over a mask, so a hit's offset in the searched text is not its offset in the file, and a hit across a removed footnote is several source ranges. Sefer needs both, plus a preview line, for every hit in a project.

## The solution

One [[ticket]]-generated buffer ([[invariants]] 2, 6). Each hit carries its projected range and a `Repeat` of source pieces; book ids and preview lines sit once in a string table. Browser and native share the encoder.

## Trade-offs

- The preview is display text only: the projected text is discarded after the search.
- The variable piece count is why ticket gained `Repeat`.
- Offsets are UTF-16; native callers convert.

## Show me

How Sefer walks the hits; note the two kinds of position per hit. From `galley/src/wasm.md`:

```js
const hits = Hits.open(galley.findAll("God", { wholeWord: true, limit: 200 }));
for (let n = 0; n < hits.hitCount; n++) {
  const hit = hits.hit(n);
  hits.id(hit.bookIndex);                  // which book
  hit.projectedFrom, hit.projectedTo;      // what to highlight
  const pieces = hit.pieces();             // where an edit lands, one per piece
  hits.preview(n);                         // the result card's line
}
```

## How it works

- **Two coordinate spaces.** Projected offsets are mask space ([[mask]]); source pieces are document bytes converted to UTF-16 ([[find]]).
- **One encoder, two doors.** The browser's `find`/`findAll` and the desktop's native `Expediter::find` both call `find::wire::encode`.
- **The id table names every book searched**, matched or not, so a hit cannot be misattributed if the corpus changed between calls.
- **`Repeat` for pieces** in [[ticket]].

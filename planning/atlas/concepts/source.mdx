## The problem

Files arrive with odd spacing, broken markers and missing book codes. Tidying any of that on load makes the engine's offsets disagree with the editor's buffer and turns every save into a diff.

## The solution

Bytes are kept as they are, and every product is positions into them ([[invariants]] 1), so saving what was loaded is identity. Only [[format]] and lint fixes propose new bytes, as [[edit]]s.

## Trade-offs

- Line endings must be LF. CRLF parses, but shifts UTF-16 offsets one per line against an editor and changes every content hash.
- Broken input is kept as data, so every later step must cope with it.
- Outputs that cannot hold everything (HTML, USJ, USX, vref) are named lossy.

## Show me

A token is just a start and a length into the file; reading it is a slice.

```text
source    \v 1 Jesus wept.
span      Token { start: 26, len: 3 }   → source[26..29] == "\v "
```

Spans tile the source. The scratch book in [[cst]] is 125 bytes and its 37 tokens cover 0..125 with no gap.

## How it works

GLOSSARY.md, "The material": Source is never normalized and never repaired on ingest. Text is source-backed: reading a token's text is a slice, never a copy of a stored string. An invalid or missing `\id` is kept as data.

- **Lossless invariant.** The token stream is an index over Source, so round trip is identity by construction.
- **Refuse, never invent.** Input that cannot be represented is refused with a reason. Only [[format]] may invent bytes, and only whitespace and fix text.
- **LF contract** (`onion-wasm/README.md`, "The contract").

## Composes with

The [[scanner]] cuts it into [[token]] spans. [[mask]] ranges, [[toc]] rows, [[edit]] splices and [[utf16]] offsets all point into it.

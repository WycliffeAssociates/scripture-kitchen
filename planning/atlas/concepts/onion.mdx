## The problem

Every structural question about a USFM book needs one implementation behind every host.

## The solution

All of it lives here, written once ([[invariants]] 4): text in, answers out, no file I/O. Caching is [[galley]]'s, and the wasm build is [[onion-wasm]]'s, so native users pay nothing for it.

## Trade-offs

- Repeated calls redo work unless the caller caches; deliberate.
- Answers are indices into the caller's text and token arrays, not owned strings or objects; the caller keeps both and slices.
- The whole book must be in memory; `lex` takes a `&str`, not a reader.

## Show me

The pipeline, text to answers:

```rust
let tokens: Vec<Token> = onion::lex(text);
let tree: Cst = onion::cst::build(&tokens);
let toc: Toc = onion::toc(text.as_bytes(), &tokens);   // no tree needed
let kept: Mask = onion::mask(text.as_bytes(), &tokens, &tree, &filter);
// lint, format_edits, diff, usj / usx / html and Toc::resolve read the same arrays
let dish: Vec<u8> = onion::wire::plate(&onion::wire::parse(text, opts)); // for JS
```

`cargo run --release --bin playground -- --toc-trace <file>` and friends regenerate the `debug/` dumps; `--bin codegen` regenerates the marker tables, the wire, `reader.ts` and `diagnostics.json`.

## How it works

- **One implementation per behaviour.** "Drivers may vary, the engine never forks" (GLOSSARY, "Engine"). Every derivation lives here, computed on demand.
- **Stateless and lossless.** No caching, no I/O (`galley/src/lib.rs`).
- **Small dependency set** (JSON writers are hand-rolled; serde is a test dependency only): `memchr`, `rustc-hash`, `similar` and `unicode-segmentation` for diff's graphemes, `xxhash-rust` for the dish hash, plus [[mise]] and [[ticket]].
- **Exports are features** (`usj`, `usx`, `html`, default on).

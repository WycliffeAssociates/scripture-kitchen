## The problem

USFM is a plain-text markup only some tools read. Other Bible software wants USJ (a JSON form of the same content), USX (an XML form), or plain HTML to show on a page. Those formats cannot hold everything the original file holds, such as the exact spacing or the order attributes were written in. Something has to convert, and it has to be clear where detail gets dropped.

## The solution

We convert from the parsed tree of the book (the [[cst]]), one writer per format. All the loss happens here, at the very end, and nowhere earlier: the engine keeps the file byte-exact until someone asks for an export. Damaged markup is reported by [[lint]], not patched up in the export, so an export never invents an "unmatched" element. The three writers share only small helpers (marker spelling, canonical forms), because JSON commas and XML closing tags need different bookkeeping.

## Trade-offs

- Exports are lossy by design. Runs of whitespace become one space; attribute order and quote style are lost; some content moves into attributes (`\ca` becomes `altnumber`).
- You cannot round-trip back to the original file from an export. Keep the USFM for that.
- HTML has no official reference to test against, so it is held only by a "same text in, same text out" rule.
- All three ship in the WebAssembly package (~370 KB, ~152 KB gzipped); a Rust user can switch each off.

## Show me

The scratch book in [[cst]], through each format (trimmed). Note `   spoke.` became ` spoke.`:

```text
USJ   {"type":"para","marker":"p","content":[{"type":"verse","marker":"v","number":"1","sid":"MRK 1:1"},
        "Jesus wept.",{"type":"note","marker":"f","caller":"+","content":[{"type":"char","marker":"ft","content":["why"]}]},
        " Then ",{"type":"verse","marker":"v","number":"2-3","sid":"MRK 1:2-3"},"he ",
        {"type":"char","marker":"nd","content":["Lord"]}," spoke."]}

USX   <para style="p"><verse number="1" style="v" sid="MRK 1:1" />Jesus wept.<note caller="+" style="f">
        <char style="ft">why</char></note> Then <verse eid="MRK 1:1" />…

HTML  <div class="usfm-p" data-marker="p" data-usfm-type="para" data-usfm-category="para-body">
        <sup class="verse-num usfm-lifted usfm-v" … data-sid="MRK 1:1">1</sup>Jesus wept.…
```

## How it works

- **The lossy view.** The [[token]] stream stays byte-identical; whitespace, attribute order, quote style and lifted content are dropped only in these folds.
- **Oracled where an oracle exists.** USJ matches 187 of 187 validated committee fixtures in `testData`, with 20 excluded, each with a reason (commit b82a2bf). HTML puts every fact in `data-*` attributes and is pinned by a text-identity invariant.
- **Separate writers, shared reads.** `export.rs` shares only canonicalization, marker spelling and note-peer sets.
- **Compile-time optional.** Cargo features `usj`, `usx`, `html`, on by default.

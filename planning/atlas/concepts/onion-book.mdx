## The problem

Sous needs verse text with chapter and verse rows and a way back to source offsets, without importing onion's types.

## The solution

sous-core defines [[code:sous-chef/core/src/input.rs#ProjectedBook]] (key, text, chapters, verses); [[code:galley/src/sous/onion_book.rs#OnionBook]] implements it in [[galley]] over the verse-text [[mask]] and the [[toc]] ([[invariants]] 7). No second index: the mask owns the projection, the TOC owns identity. A finding maps back as a list of source pieces, since it can cross a removed note.

## Trade-offs

- Verses must ascend. An out-of-order verse abstains, and [[lint]] reports it.
- It keeps the longest ascending run, so one stray verse number drops only that verse.
- Sous cannot judge anything only markup carries (poetry lines, footnote text): it sees verse text and numbers.

## Show me

From `galley/src/sous/onion_book.rs`. The footnote is gone from the text, and `locate` returns two raw pieces around it:

```rust
let book = OnionBook::parse("\\id MRK\n\\c 1\n\\p\n\\v 1 Jesus \\f + \\ft note\\f* wept.\n")?;
book.text();       // "Jesus  wept.\n": verse text, markup gone
book.chapters();   // [Chapter 1 at 0..13]
book.locate(0..13); // MRK 1:1, raw runs [21..27, 43..50]: two pieces around the note
```

Out-of-order verses abstain:

| verses in order | abstains |
| --- | --- |
| `\v 22 \v 23 \v 24 \v 23 \v 25` | the second 23 |
| `\v 22 \v 23 \v 42 \v 25 \v 26` | 42, not 25 and 26 |

## How it works

- **sous-core never depends on onion.** It takes a borrowed `ProjectedBook`. Onion stays the USFM authority; Sous sees projected ranges and numeric units (`charter.md`, "Ownership boundaries").
- **Ascending verses** come from a patience sort keeping the longest ascending run.
- **`from_parts` rebuilds from retained products** without lexing again; `locate` walks only the ranges it returns.

## Composes with

Built from a [[mask]] and [[toc]]; consumed by [[chapter-pass]]es in [[sous-core]]; built per book by the [[expediter]] and the cold `publish_onion_findings`, whose results become the [[findings-snapshot]].

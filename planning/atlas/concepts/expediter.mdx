## The problem

Sous findings are corpus-relative, so a keystroke in Mark can move a verdict in Genesis, and Sefer asks for findings after edits. Rerunning every pass over every book per publish is too slow, and any reuse must still equal a cold run.

## The solution

An update only stores; the work happens at publish ([[invariants]] 4, 5). Then it maps only chapters whose bytes changed, refolds only books whose aggregates moved, and rejudges, all from content-keyed stores. The two most recently edited books keep their chapter observations hot. Every publish is a whole snapshot, never a patch, and `tests/equivalence.rs` holds it to a cold run.

## Trade-offs

- The first publish pays for everything.
- A config change re-places findings in every book: 3.2 ms for 66 books, against 206 µs for an unchanged republish.
- Hot books' observations cost 281 KB of rows on en_ulb.

## Show me

From `galley/src/sous/expediter.md`: the second publish reads nothing.

```text
sous.update("books/mrk.usfm", Role::Target, &text)?
sous.publish()?          -> SOUS corpus buffer, raw-book UTF-16
sous.last_mapped()       -> 6      // six chapters mapped
sous.publish()?          -> the same bytes
sous.last_mapped()       -> 0      // nothing re-read, nothing re-mapped
```

```text
1 index   chapter table hit? skip : OnionBook::from_parts → ObservationKey per chapter → map / remap
2 fold    books with no aggregate
3 tally   untally the old aggregate, tally the new, name the moved word keys
4 judge   every Target aggregate, re-deciding only the named keys
5 pair    each Target against its Reference
6 locate  replay cached site rows, or rescan text
7 sweep   drop what no ring names
8 rebase  through each book's retained mask and UTF-16 table, then encode
```

## How it works

- **Index at publish, not update.** Ten updates and one publish pay one pass over ten books. Projected text is never retained; reprojecting costs ~38 µs a book.
- **Judging is corpus-level.** Step 4 runs over every aggregate. Steps 3–4 move one book at a time: re-merging all rows was 4.7 ms of a 4.9 ms warm republication.
- **The hot set.** With two hot books the second keystroke maps 1 chapter of MRK instead of 16.
- **A config change is a re-judge, never a re-map.** Config is in no cache key except `verdicts`.
- **Same bytes native and in JS.** `sous_goldens.rs`, `wasm_wall.rs` and `sous_conformance.mjs` pin one set of goldens (`wasm.md`, "The claim").

## The problem

USFM files are typed by hand, so they contain mistakes: a footnote never closed, verse 3 before verse 2, a verse number skipped. The editor needs to underline each one as the translator types and, where it is safe, offer a one-click fix. It must never quietly change the text, because the editor's cursor positions depend on the file staying exactly as typed.

## The solution

We walk the parsed book (the [[cst]]) once, in order, and report each problem as a code plus positions. Problems the parser already noticed, like a footnote that never closed, are read from the parser's verdict, not worked out a second time. Each finding is just four numbers, so a whole report crosses to JavaScript as one flat array; the message text lives in a separate file, `diagnostics.json`. A fix is only an offer: a list of [[edit]]s the editor may apply. Fixes that would need a guess or a move are not offered.

## Trade-offs

- No automatic repair. Lint flags; the translator or editor decides.
- Some fixes are never offered, such as guessing which book code was meant or moving an attribute list.
- Findings carry no text, so every consumer needs `diagnostics.json` to show a message.
- Some severities depend on the USFM version the file declares, so the same text can lint differently depending on its `\usfm` line.

## How it works

Three laws from `lint.rs`:

- **Read verdicts, never re-derive them.** `unclosed-note` is the [[walker]]'s `Recovery` on the `\f` node, matched, not recomputed.
- **Flag, never repair.** No token is moved, inserted or dropped. A `Fix` exists iff the row declares a `fix_label`, and `check_fixes` proves them over all 226 corpus books.
- **No strings.** An `Observation` is four `u32`s: anchor and second are token indices, `aux` means what the row's `aux` column says.

One in-order walk feeds four state machines (structure, ancestry, ordering, flat). `diagnostics.json` lists 59 codes in six categories (structure, ordering, attributes, payload, form, version). 11 have severity `form`: the Form channel, which only [[format]] evaluates. The `lint.rs` doc's "48 codes" is the count without them. `declared_version` rides on every report and two rules are gated on it. ~9.4 ns/token on en_ulb, ~15.5 on en_ult; the gap is the k/v attribute rules over 31 MB of `\w` interiors.

Sefer reported, 2026-10-21:

> The engine's marker registry is process-wide (onion/src/extensions.rs, static REGISTRY), so two editors on one page with different marker configs interfere. The package documents one config per page; a per-call or per-handle registry would be a kitchen ask.

Will, 2026-10-21: Sefer puts reference texts next to main texts. Kept separate from 0.1.12.

## What a user gets

A main text and its reference texts, from projects with different `markers.ext`, on one page and one `Galley`, each parsing its `\z` markers by its own project's list, and no registration flushing another book's caches.

```ts
import { Galley, customMarkers, customMarkersFromMarkersExt, type CustomMarkers } from "@…/galley";

const mine: CustomMarkers = customMarkersFromMarkersExt(myMarkersExt);
const theirs = customMarkers([{ name: "zfoo", category: "char" }]);
// → { markers: [{ name: "zfoo", category: "char" }], relaxZPrefix: false, malformed: [] }

galley.update("books/MRK.usfm", text, { customMarkers: mine });
galley.updateReference("ref/MRK.usfm", refText, { customMarkers: theirs });
galley.resolveOf(refText, address, { customMarkers: theirs });
// no customMarkers option: the global setCustomMarkers list
```

## Why it is small

The engine already takes the list explicitly: `lex_with(source, &Extensions)` (`onion/src/scanner.rs`); `lex()` is `lex_with(source, &current())`. The tree, lint and toc never read the registry: a custom marker resolves at lex time to the row of the category it behaves as. The global appears only at the `lex()` calls in galley (`pantry/chunks.rs`, `sous/mod.rs`, `sous/onion_book.rs`, `mask/mod.rs`) and onion-wasm's free doors.

## What changes

- `CustomMarkers`: a plain object with a branded TypeScript type, `{ markers, relaxZPrefix, malformed }`, made by onion-wasm's `customMarkers(list, opts?)` or `customMarkersFromMarkersExt(text)` and re-exported by galley. `markers` holds the entries kept and `malformed` the ones refused. A door reads `markers` and `relaxZPrefix`, checks the shape, refuses an entry the registry would not keep, and interns the list: equal lists share one `Arc<Extensions>`, which a registered book keeps and lexes through `lex_with`. There is nothing to free.
- The chunk store keys on content and the book's custom markers, so the same bytes under two lists never share a parse.
- Re-registering a book with another list re-derives that book alone. The caller holds no generation; the global generation stays only for books on the global list.
- Every door that parses loose text takes the same optional `customMarkers`: onion-wasm's free doors (`parse`, `mask`, `resolve`, …) and galley's `…Of` doors (`maskOf`, `resolveOf`, `structureTextOf`, `verseTextOf`). Without it they read the global list, as today.

The JS names that said "extensions" say "custom markers", so one word runs through the surface (Will, 2026-10-22: Sefer is the only consumer and the rename is small). The Rust names inside onion stay.

| Now | Becomes |
|---|---|
| `setExtensions(list, opts?)` | `setCustomMarkers(customMarkers(list, opts?))` |
| `extensionsFromMarkersExt(text)` | `customMarkersFromMarkersExt(text)`, the object rather than JSON |
| `ExtensionOptions` | `CustomMarkerOptions` |
